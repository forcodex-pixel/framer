# uvm_poe 方案数据结构位宽总表

> 用途：核对全方案数据结构定义完整性。已定义的写实际位宽；未定义的标 **待定**；
> 模型占位用 `（占位）` 标注。请检查后在表格中补充位宽。

## 1. KO 报文（48B = 384bit，6×8B）

### 1.1 第一行（8B，所有模板相同）

| 字段 | 位宽 | 含义 |
| --- | --- | --- |
| DA | 1B | 宿端地址 |
| DP | 1B | 宿端端口 |
| SA | 1B | 源端地址 |
| SP | 1B | 源端端口 |
| TYPE | 1B | 报文类型 |
| PRI | 3bit | 优先级（0 最高） |
| SN | 13bit | 序号 |
| B/E/LBO(CHN) | 1B | 边界/末标记/低字节优先（通道），内部位域待定 |

### 1.2 四种模板（第 2~6 行，40B）

| 模板 | 内容 | 未定义部分 |
| --- | --- | --- |
| KO 开销报文 | 第 2 行 8B + 第 3 行前 4B = 开销头，其余 META | 开销头字段、META 细分布宽 |
| KO IO 报文 | 除第 1 行外全 META | META 细分布宽 |
| KO 控制报文 | 第 2 行 = 控制头，其余 RES | 控制头字段、RES |
| KO DMA 报文 | 第 2~3 行 = DMA META，其余 RES | DMA META 字段、RES |

## 2. burst（38bit，已定义）

> 一种结构、两种类型，由 `burst_type` 区分（0=i/v_task，1=c_task），字段不完全相同：
> 部分字段按类型复用同一比特位（i/v 与 c 字段重叠布局）。
> 锁字段（lock_id/unlock_req/lock_req）为公共字段，**仅在 ts 首个 burst（st=1）生效**。

| 字段 | 位宽 | 适用类型 | 含义 |
| --- | --- | --- | --- |
| lock_id | 4bit | 公共 | 锁 ID（0..15，仅 st=1 有效） |
| unlock_req | 1bit | 公共 | 解锁请求（仅 st=1 有效，该 ts 完成时释放锁） |
| lock_req | 1bit | 公共 | 加锁请求（仅 st=1 有效，该 ts 首个 burst 发射时获取锁） |
| st | 1bit | 公共 | 是否为所属 ts 的首个 burst |
| tr | 1bit | 公共 | 是否涉及 O 窗操作 |
| ts_len | 3bit | 仅 i/v | 所属 ts 包含 burst 数 |
| branch | 1bit | 仅 i/v | 是否可能存在 ts 跳转 |
| rev | 4bit | 仅 c_task | 保留位（与 iv 的 ts_len+branch 复用 4bit） |
| burst_type | 1bit | 公共 | 0=i/v_task，1=c_task |
| vld_cu | 1bit | 公共 | 需执行 task 数：0=1 个，1=2 个 |
| tsk_id0 / tsk_id1 | 3bit / 3bit | 仅 i/v | 任务 id，查 CSR.vtsk_c（与 dma_id0/1 复用 6bit） |
| c0 / c1 | 1bit / 1bit | 公共 | 任务0/1 有效标志（0=无效） |
| sub_pc0 / sub_pc1 | 8bit / 8bit | 仅 i/v | task 指令集指针（与 occ_ts0/1 复用 16bit） |
| dma_id0 / dma_id1 | 3bit / 3bit | 仅 c_task | 任务 id，查 CSR.dma_c |
| occ_ts0 / occ_ts1 | 8bit / 8bit | 仅 c_task | c_task 占据的 ts 数 |

位宽核对：`lock_id4+unlock1+lock1+st1+tr1+[ts_len3+branch1|rev4]+burst_type1+vld_cu1+[tsk_id6|dma_id6]+c0/c1 2+[sub_pc16|occ_ts16] = 38bit`。

## 4. CSR 表项（每线程 1 项）

| 字段 | 位宽 | 含义 | 状态 |
| --- | --- | --- | --- |
| err | 1B | 线程错误指示（默认 0） | 刷新条件待定 |
| ccr | 8B | 待定 | 语义待定 |
| sys_ts | 6B | 系统时戳（线程启动时间） | 已定义 |
| th_id | 6bit | 线程 id（64 线程） | 已定义 |
| th_stat | 1B | 线程状态（IDLE/READY/ISSUED/DONE） | 已定义 |
| o_mes | 1B | O 窗操作/状态指示 | 语义待定 |
| cur_ts | 1B | 当前 ts | 已定义 |
| vtsk_c | 1B | i/v 任务执行掩码（tsk_id 查询） | 位宽已定义，用途待 CU 实现 |
| dma_c | 1B | c_task 执行掩码（dma_id 查询，8bit 对应 cw 8 项） | 已定义 |
| tw | 8×1B | 待定 | 语义待定 |
| cw | 8×6B | c_task 操作表（dma_id 索引） | 条目位域见 4.1 |

### 4.1 CSR.cw 条目（6B = 48bit，已定义）

| 字段 | 位宽 | 含义 |
| --- | --- | --- |
| tag | 20bit | smc 地址（= op_addr） |
| op_type | 1bit | loc/free：0=loc，1=free |
| r | 1bit | c_line 有效；smc 读出数据刷新 c 窗 c_line 后写 1 |
| o | 1bit | 1=该线程占据该 c 窗资源 |
| c_line_num | 8bit | c 窗资源号：独享 = tid×4+dma_id[1:0]（0..255）；共享 = FIFO 资源号（0..255） |
| start_ts | 8bit | 起始 ts |
| occ_ts | 8bit | 占据 ts 数 |
| rsv | 1bit | 保留 |

位宽核对：`20+1+1+1+8+8+8+1 = 48bit`。

> cw 8 项固定映射：**dma_id 0..3 → 独享资源**（每线程固定位置），**dma_id 4..7 → 共享资源**（FIFO 分配）。
> 每线程同时 lock 的不同 dma_addr 最多 8 个（cw 8 项）。

## 5. C 窗

| 结构 | 定义 | 状态 |
| --- | --- | --- |
| C 窗（独享） | 64（线程）× 4（固定位置）= 256 项；位置 = tid×4+k（k=0..3） | 条目 168bit（21B） |
| C 窗（共享） | 256 项，由 dma_ctrl 资源管理 FIFO 分配 | 条目 168bit（21B） |
| C 窗资源池 FIFO | 256 深 × 资源号 8bit（仅管理共享资源） | 已定义 |
| 单线程共享占用上限 | 4（对应 cw 后 4 项） | 已定义 |

> C 窗资源生命周期完全由 c_task 控制（lock/free 成对出现），**线程结束不兜底归还**；
> 独享位置申请/释放不经过 FIFO，共享资源经 FIFO 分配/归还。

### 5.1 C 窗资源条目（168bit = 21B，已定义）

| 字段 | 位宽 | 含义 |
| --- | --- | --- |
| tag | 20bit | smc 地址 |
| c_line | 128bit | 行数据（free 时经 RBA 写 SMC） |
| d | 1bit | 数据 dirty：申请后 0，CU 改写 c_line 后 1 |
| o | 1bit | 占用标志：申请到资源后写 1 |
| r | 1bit | c_line 有效：smc 读出数据刷新 c 窗 c_line 后写 1 |
| cnt | 9bit | 老化计数：超上限强制释放（o=0，资源号入 FIFO） |
| ind | 8bit | c 窗资源号（64×4=256 个资源） |

位宽核对：`20+128+1+1+1+9+8 = 168bit`。

## 6. 指令预存资源

**已删除**：THM 线程级互斥锁保证同一 smc 地址同一时刻只有一个线程执行，不再存在
"loc 命中他人已 lock 地址 → 等待转交"的场景，指令预存资源（16 深）随扫描查重/
转交逻辑一并移除。

| 信号 | 位宽 | 含义 |
| --- | --- | --- |
| 输入流（7 路）vld / rdy | 1bit | 握手 |
| 输入流 pri | 3bit | 报文优先级 |
| 输入流 cid / pos | 17bit / 3bit | 通道/位置（串口不带） |
| 输出 vld / rdy | 1bit | 握手 |
| 输出 pri / src / stream | 3bit | 优先级 / 组号 / 来源流 |
| 输出 cid / pos | 17bit / 3bit | 通道/位置 |

## 14. 线程描述（激励旁路，模拟 I_BUF_A；占位）

**线程模板池**（`uvm_poe/rtl/poe_thread_tpl.sv`，`poe_thread_tpl_pkg`）：THM 建线程时
随机选取模板（`tpl_get(idx)`），替代 tb_top 旁路随机生成。

| 模板字段 | 位宽 | 含义 |
| --- | --- | --- |
| ts_cnt | 5bit | ts 数（1..16） |
| ts_bs | 48bit | 每 ts burst 数（16×3bit，ts0 固定 1） |
| ts_id | 96bit | 每 ts 编号（16×6bit，递增可跳转） |
| pri | 3bit | 线程 burst 优先级 |
| burst_seq | 2432bit | 每 ts burst 模式（16×4×38bit，含 ts 级锁字段） |
| vtsk_c | 8bit | CSR vtsk_c 初始化 |
| dma_c | 8bit | CSR dma_c 初始化 |
| cw | 384bit | CSR cw 初始化（8×6B） |

已准备 6 个模板（`N_TPL=6`）：

| 模板 | 场景 |
| --- | --- |
| T0 短 i/v | 2 ts 纯计算，无 c_task / 无锁 |
| T1 混合 | 4 ts，1 对共享 c_task（loc/free） |
| T2 长+branch | 8 ts，ts 编号跳转，1 对共享 c_task |
| T3 DMA 密集 | 5 ts，3 对 c_task（独享 2 对 + 共享 1 对） |
| T4 单段持锁 | 5 ts，ts0 lock / ts3 unlock（锁 ID 0） |
| T5 双段持锁 | 6 ts，两段锁（lock/unlock 各两处） |

## 17. ts 级互斥锁（THM，已定义）

| 结构 | 定义 | 说明 |
| --- | --- | --- |
| 锁表 | 16 项 × 6bit | 每项存持锁线程 tid；63=空闲；锁 ID 独立编号（0..15） |
| 锁声明 | burst 公共字段 lock_id/unlock_req/lock_req（仅 st=1 有效） | 不再从 KOA 旁路输入 |
| 锁生命周期 | lock_req ts 首个 burst 发射时获取；unlock_req ts 完成时释放；线程结束兜底 | 一段 ts 持锁；同锁线程 ready_mask=0 等待 |
| 关联 smc 冲突 | 同一锁 ID 同一时刻只有一个线程执行 | 从根源避免多线程并发操作同一 smc 地址 |
